# 术语表 —— 英文词统一口径

> **这份表不负责解释代码，只负责「同一个英文词，全项目译成同一个中文」。**
> 具体解释仍然写在代码里（术语首次出现处的注释），这份表是查口径用的。
>
> 建立于 2026-09-19。起因：读代码时"有的能读懂、有的读不懂"，逐文件加标注时
> 必须有唯一口径，否则同一个 `evaluator` 在 10 个文件里会有 10 种译法。

## 怎么用

1. **读代码卡住时** —— 按词查这里的「统一译名」和一句话解释，再回代码看上下文。
2. **改代码时** —— 注释里要提某个英文词，译名用本表的，别另起一个。
3. **写新文件时** —— 术语首次出现处标一次（见下方「标注约定」）。

## 标注约定

| 规则 | 取值 |
|---|---|
| 标注位置 | 同一术语**在同一个文件里首次出现处标一次**，后面重复出现不再标 |
| 标注形式 | 注释/文档字符串里：`evaluator（评估器）`；代码标识符/字符串用行尾 `#` 注释 |
| 译名来源 | 本表。表里没有的新词，先加进本表，再统一使用 |
| 硬约束 | **只加注释和文档字符串，不改任何可执行逻辑** —— 改动后用「剥离注释比对 AST」验证（做法见 [idea.md](idea.md)） |
| 注释内容 | 说明**为什么**和**是什么机制**，不复述代码在做什么 |

## A. 编排与图（LangGraph）

| 英文 | 统一译名 | 一句话解释 |
|---|---|---|
| LangGraph | 图编排框架 | 把多步流程画成图的框架：节点干活，边决定下一步走谁 |
| node | 节点 | 图上一个干活的函数 |
| edge | 边 | 决定"这一步做完走谁" |
| conditional edge | 条件边 | 不写死下一个节点，调用函数、用它的返回值查映射表来定 |
| START / END | 虚拟起点 / 终点 | 图的入口与出口标记，本身不是节点 |
| state | 状态 | 全图共享的数据字典，节点靠读它、往它里写返回值来传数据 |
| reducer | 归并函数 | 声明同一字段被多个节点并发写入时怎么合并（如 `operator.add` 累加） |
| Annotated | 类型标注 | 把 reducer 挂到某个字段上的写法，如 `Annotated[List, operator.add]` |
| Send | 分发指令 | "把这份数据送给某个节点"，用于一个节点扇出成多个并行分支 |
| DAG | 有向无环图 | 有依赖顺序、且不能绕回自己的任务图 |
| fan-out / fan_out | 扇出 | 一个节点同时把任务发给多个下游，并行执行 |
| wave scheduler | 波次调度 | 有依赖的 DAG 不能全并发，每轮只发"依赖已全部完成"的那批 |
| checkpointer | 检查点 | 每走完一步就把 state 存一份快照，暂停/恢复全靠它 |
| MemorySaver | 内存存档器 | 内置 checkpointer，快照存在内存里，进程重启即丢 |
| interrupt_before | 执行前中断 | 走到某节点之前先停下，把控制权交回调用方 |
| checkpoint | 检查点快照 | 某个时刻 state 的存档 |
| compile | 编译 | 把"画好的图纸"变成能真正执行的图 |
| thread_id | 会话 ID | 隔离不同对话窗口/用户的记忆，互不串味 |
| node name | 节点名 | 连边时引用的字符串，必须和 add_node 时一致 |

## B. 编排角色（本项目的各个节点）

| 英文 | 统一译名 | 一句话解释 |
|---|---|---|

| router | 路由器 | 简单问题：挑一个最合适的 Agent |
| planner | 规划器 | 复杂问题：拆成带依赖关系的任务列表 |

| parameter_aligner | 参数对齐器 | 按 `parameter_mapping` 从上游结果里提取、补齐下游要的入参 |
| human intervention | 人工介入 | 流程暂停，等真人确认后再继续 |
| retry | 重试 | 质量不达标就回头再跑 |
| iteration | 迭代轮次 | 当前是第几轮重试 |

## 附：术语的译名为什么这么定

两个原则，都是为了"看起来不费劲"：

1. **优先用中文习惯叫法，而不是字面直译。**
   例：`aggregator` 译"聚合器"而不是"汇总者"；`critic` 译"评审"而不是"批评家"。
2. **译名必须能在中文里独立成句。**
   `fan_out` 译"扇出"是因为中文里已有这个词（电路/流程设计的既有说法），
   而"扇出到多个分支"能直接读通；如果只想得到"分发"，会和 `Send` 撞义。

**最容易译错的一个是 `critic`** —— 字面看像"给输出打分"，实际是**校验任务衔接**
（[critic.py](langgraph_orchestrator/critic.py) 找的是下游任务）。
猜错的注释比没有注释更糟：读者会带着一个错误的模型继续往下读。
