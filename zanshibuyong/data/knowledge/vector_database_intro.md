# 向量数据库完全指南

## 什么是向量数据库

向量数据库（Vector Database）是一种专门用于存储、索引和查询高维向量数据的数据库系统。它通过将非结构化数据（如文本、图像、音频）转换为向量表示，实现高效的相似度搜索和语义检索。

### 核心概念

**向量（Vector/Embedding）**
- 将数据转换为固定维度的数值数组
- 例如：文本 "向量数据库" → [0.23, -0.45, 0.67, ..., 0.12] (1536维)
- 语义相似的数据在向量空间中距离更近

**向量化（Embedding）**
- 使用深度学习模型将原始数据转换为向量
- 常用模型：BERT、Sentence-BERT、OpenAI text-embedding、DashScope text-embedding-v2
- 向量维度通常为：512、768、1024、1536、3072等

**相似度度量**
- **余弦相似度（Cosine Similarity）**：最常用，范围[-1, 1]，值越大越相似
- **欧氏距离（L2 Distance）**：计算向量间的直线距离
- **内积（Inner Product）**：向量点乘，适合归一化向量

## 向量数据库的核心技术

### 1. 索引算法

**HNSW（Hierarchical Navigable Small World）**
- 原理：构建多层图结构，每层是一个小世界网络
- 优势：查询速度快（毫秒级）、召回率高（>95%）
- 劣势：内存占用大、构建时间长
- 适用：中小规模数据（百万-千万级）

**IVF（Inverted File Index）**
- 原理：将向量空间划分为多个聚类，查询时只搜索相关聚类
- 优势：内存占用小、支持大规模数据
- 劣势：召回率略低、需要调参
- 适用：大规模数据（亿级以上）

**PQ（Product Quantization）**
- 原理：向量压缩技术，将高维向量压缩为短码
- 优势：极大降低内存占用（10-100倍）
- 劣势：精度损失、查询速度略慢
- 适用：超大规模数据、内存受限场景

### 2. 距离计算优化

**SIMD加速**
- 使用CPU的SIMD指令集（AVX2、AVX512）
- 并行计算多个向量的距离
- 性能提升：4-8倍

**GPU加速**
- 利用GPU的并行计算能力
- 适合批量查询、大规模索引构建
- 性能提升：10-100倍

**量化技术**
- Float32 → Float16：减少50%内存，精度损失<1%
- Float32 → Int8：减少75%内存，精度损失2-5%

### 3. 混合检索

**向量检索 + 关键词检索**
```python
# 向量检索（语义相似）
vector_results = vector_db.search(query_embedding, top_k=100)

# 关键词检索（精确匹配）
keyword_results = bm25.search(query_text, top_k=100)

# RRF融合（Reciprocal Rank Fusion）
final_results = rrf_merge(vector_results, keyword_results)
```

**向量检索 + 元数据过滤**
```python
# 先过滤元数据，再进行向量检索
results = vector_db.search(
    query_embedding,
    filter={
        "category": "技术文档",
        "date": {"$gte": "2024-01-01"},
        "author": {"$in": ["张三", "李四"]}
    },
    top_k=10
)
```

## 常见问题

**Q1: 向量维度越高越好吗？**
A: 不一定。更高维度可以捕获更多信息，但也会：
- 增加存储成本
- 降低查询速度
- 可能导致"维度灾难"
- 建议：512-1536维是较好的平衡点

**Q2: 如何选择相似度度量？**
A:
- 余弦相似度：最常用，适合大多数场景
- 欧氏距离：适合向量已归一化的场景
- 内积：适合推荐系统

**Q3: 向量数据库能替代传统数据库吗？**
A: 不能完全替代。向量数据库专注于相似度搜索，传统数据库专注于精确查询和事务处理。实际应用中通常是混合使用。

**Q4: 如何评估向量检索的效果？**
A:
- 召回率（Recall）：检索到的相关文档占所有相关文档的比例
- 精确率（Precision）：检索到的相关文档占所有检索结果的比例
- MRR（Mean Reciprocal Rank）：第一个相关结果的排名倒数的平均值
- NDCG（Normalized Discounted Cumulative Gain）：考虑排序质量的综合指标

**Q5: 向量数据库的成本如何？**
A:
- 开源方案：免费，但需要自己运维
- 云服务：按查询量或存储量计费，通常$0.1-1/百万次查询
- 硬件成本：主要是内存和存储，1亿向量约需100-500GB内存
